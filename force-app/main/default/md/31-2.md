## 2. 整合性チェックの受け渡し（LWC ⇔ Apex）

- メソッド：`Juj_JigyoCsvUploaderController.checkCategory2(String requestJson)` → `{ errors: List<CheckError> }`
- 整合性チェックは LWC（取込データの他事業との重複：No.62・63・82・83 の取込データの部分）と Apex（既存データ）を並行して行う（Apex の呼出しを先に開始する。11/09）
- 呼出し：行（6 ファイルの合計）を 2,000 行ずつに分け、順番に呼び出す（並列にしない。事業の途中で分かれる場合がある）【F-7】
- ユーザ種別・支部コードはリクエストで受け取らず、Apex で取得する
- Apex は without sharing（他支部の割当・実績 等も判定に使う）。会ごとの番号のマスタ（従事場所・支部・相談員）のみ with sharing【C-16】
- リクエスト：`{ jigyoList: [ { key, jigyoNo, basyoNo, nendo, hasCsvJigyo, hasCsvMeisai, csvJigyoFlags, rows: [ { fileKey, lineNo, data, csv～ } ] } ] }`
  rows はその呼出しの行のみ。同じ事業の他の行との関連は、LWC が事業の全行から求めて次の項目で渡す（Apex は呼出し内の行どうしで判定しない）

| 項目 | 内容 | チェック No. |
|---|---|---|
| hasCsvJigyo | 取込データに従事事業の行がある | 29 |
| hasCsvMeisai | 取込データに従事事業明細の行がある | 61・81 |
| csvJigyoFlags | 取込データの従事事業の応募時入力項目フラグ 8 項目（従事事業の行がない場合は null）| 42～47 |
| 行.csvHasOuboMeisai | 応募：同じ登録番号の応募明細がある | 43 |
| 行.csvHasOubo | 応募明細：同じ登録番号の応募がある | 51 |
| 行.csvHasMeisai | 応募明細・割当・実績：同じ日の従事事業明細がある | 52・61・81 |
| 行.csvMeisaiJikantai | 応募明細・割当・実績：同じ日の明細の時間帯（「HHmm-HHmm:人数;…」、または「DEFAULT:募集人数」＝従事場所マスタの時間）| 52・61・64・81 |
| 行.csvFlaggedBySlot | 明細：同じ日の 割当フラグ＝1 または 確定フラグ＝1 の割当の件数（時間帯ごと「HHmm-HHmm:件数;…」）| 36 |
| 行.csvFlaggedCount | 割当：同じ日・同じ時間帯の 割当フラグ＝1 または 確定フラグ＝1 の割当の件数 | 64 |
| 行.csvHasJisseki | 割当：同じ登録番号・同じ日・同じ時間帯の実績がある | 65 |

- エラー：`{ fileKey, lineNo, checkNo, messageId, x, y, z }`。文言は LWC で作る。同じ行ではチェック No. の順
- 既存データはオブジェクトごとに IN 条件でまとめて取得する（`Juj_JigyoCsvCheckService`）
- Apex で例外が発生した場合：画面にその内容を表示し、登録しない
- 登録直前の再チェック（No.54 を除く）は「32-2」2 章
