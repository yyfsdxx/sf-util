# 38 従事事業 入力規則 追加案

> 作成：2026/11/09。「31」の入力チェックのうち、オブジェクトの入力規則にできるものの一覧と設定値（設定画面にそのまま貼り付けられる形）
> API 名・選択リストの値は dev1 実機（「36」）で確認済み。既存の入力規則は従事事業の 15 件のみ（「23」1 章、E-8）
> 入力規則は 登録経路に関係なく すべての保存（各画面・マイページ・バッチ・データ移行・CSV 登録）で動く。CSV のチェックはそのまま残し（行ごとのエラー表示のため）、入力規則は保存時の最終防御とする

## 0. 追加前の注意

- 入力規則は他機能（応募画面 JUJ080・081、一括割当、実績・支払、データ移行）にも効く。A は「どの経路でも必ず成り立つ条件」、B は 他機能の動き・未確定事項（「27」）に影響するため リーダー・各担当の確認後に追加する
- 追加後は、条件に反する既存レコードを更新しようとするとエラーになる（入力規則は作成・更新の両方で動く）
- 入力規則は兜底（最終防御）。チェックは CSV チェック（「31」）・各画面のチェックで行い、入力規則に任せない。CSV チェックと入力規則の条件は同じにし、片方を変える場合は両方を直す（CSV チェックを通過したデータが入力規則で止まると、その事業の登録が失敗する。「31」4.(4)）
- エラーチェック定義シート（D-51）に記載する場合は 区分＝入力規則、作成理由＝下表の「チェック No.」
- エラーの単位・メッセージは CSV チェックと同じにする（1 項目ずつエラーになるチェックは項目ごとに 1 規則。11/09 本人）。メッセージは現行メッセージ一覧（「30」）の文言（ID は付けていない）。CSV の値（コード）を示す箇所のみ選択リストの値に置き換えた（A-5「0」→「省略可」、B-1「2（不可）」→「不可」）。既存の 15 件は独自の文言のため、合わせる場合は変更する
- 選択リストは ISPICKVAL、空の判定は ISPICKVAL(項目, '') を使う（選択リストに ISBLANK は使えない）
- 実施年度内の判定（A-8～A-11）は 親の従事事業の 実施年度（4 桁の半角数字。既存規則 6 で保証）を使う

## 4. 入力規則にしないもの

| チェック No. | 理由 |
|---|---|
| 1～5 | ファイル単位のチェック |
| 6・7・9 | 項目定義（必須は画面のレイアウト、桁はテキストの長さ、コード値は 値を制限した選択リスト）で既に担保されている。CSV 固有の必須（省略可の判定）は新レイアウトによる |
| 8 | 従事事業No.・実施年度 は既存規則 5・6。日付・時間・数値は項目の型で担保 |
| 10～13 の前半・15・16 | 既存規則 7・10・11・14・15・2～4 |
| 17・20・26・27 | 取込ユーザの種別・支部による判定（ユーザごとの権限・共有で扱う。G-18）|
| 19・24・34・35・38・41・49・53・57・60・75・80 | キー重複。入力規則では他のレコードを検索できない（一意にするには 一意の項目＋値の設定が必要。G-8）|
| 21・22・28・29・39・50・58・76～79 | 存在チェック。参照項目で担保（CSV ではコード→レコードへの変換で判定）|
| 23 | 既存規則 1 |
| 25・30 | 一括割当中の判定（バッチ処理ステータス）。保存時に毎回止めると一括割当の処理自体が止まるため不可 |
| 36・64 | 募集人数超過。他のレコード（割当）の件数が必要 |
| 43・51・52・54・61・62・63・65・66・81～83 | 他のレコードの有無・重複 |
| 59 | 懲戒処分等履歴 の検索が必要 |
| 67 | 親税理士番号・法人番号・法人枝番 は新では数式（会員・事務所・法人 から取得）のため、入力の相関はない |
| 72 | 支払項目は支払処理で設定するため、入力規則にすると支払処理が止まる（CSV 固有の制約）|
